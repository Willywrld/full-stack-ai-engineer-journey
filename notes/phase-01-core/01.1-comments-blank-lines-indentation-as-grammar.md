## 1. How Python reads your file (context)

Before we talk about what's ignored, we need to know what's read. Python goes through four stages:

1. **Source code** — the `.py` text you wrote.
2. **Lexer / tokenizer** — splits the text into small meaningful pieces called **tokens**.
3. **Parser** — checks whether those tokens are arranged according to Python's grammar.
4. **Execution** — only after parsing does Python actually run the program.

A **token** is the smallest meaningful unit of source code: an identifier (`x`), a number (`42`), a string (`"hello"`), an operator (`+`, `=`), a keyword (`if`, `for`, `def`, `return`), or a newline marker.

Two grammar layers matter here:

- **Lexical grammar** — rules for forming *tokens* from characters. *What counts as a valid name? What starts a comment?*
- **Syntactic grammar** — rules for arranging *tokens* into valid statements and expressions. *Is `x = 1` a valid arrangement? (`yes`) Is `x y`? (`no`)*

Comments are decided at the lexical level. Indentation and newlines are decided at the syntactic level.

## 2. What's ignored, and what isn't

| Item | Ignored? | Why |
|---|---|---|
| **Comments** | ✅ ignored by interpreter | for humans |
| **Blank lines** | ✅ mostly ignored in scripts | for humans (grouping) |
| **Whitespace (indentation)** | ❌ **meaningful** | defines blocks / suites |
| **Newlines** | ❌ **meaningful** | end-of-statement in most cases |

**Whitespace** = spaces, tabs, and similar invisible characters.

The rule of thumb:

> Comments and blank lines are mostly for humans. Indentation and newlines are part of the grammar.
