# Part A — The Concept Ladder

## §1 — Syntax, Statements, Expressions

### 1. The problem this solves
Python is like a very strict boss: if you don't follow instructions *exactly* it refuses to run the code. When you type code, you must follow two rules: one for *what you mean* (syntax) and one for *how you type it* (whitespace and layout). Breaking either rule stops your program dead.

### 2. Mental model
Think of the language as a sentence diagram:
- **Syntax** is the grammar (what makes a valid sentence).
- **Statements** are the sentences (a complete thought doing an action).
- **Expressions** are the phrases (a fragment that produces a value).

### 3. Full syntax — the three things you need right now
In Python, there are three things that matter:
1. **Expression**: anything that produces a value.
   ```python
   print("hello", "world")  # expression? Actually NO. It's a statement!
   ```
2. **Statement**: an instruction that does something. A `print` statement prints text to the screen. A `for` loop statement repeats a block of code.
3. **Expression statement**: an expression used as a statement. If it produces a value but you aren't doing anything with that value, it's an expression statement.
   ```python
   "hello"  # expression statement (produces a value but nothing happens)
   ```
4. **Whitespace**: spaces and tabs. Python is very particular about whitespace. It uses indentation to group code. You must indent the same amount (usually 4 spaces) for lines that belong together.

### 4. Behavior step-by-step
When Python executes a script:
1. It reads the file line by line.
2. It ignores blank lines and lines starting with `#` (comments).
3. It checks the syntax of each line.
4. If syntax is valid, it executes the line.
5. If syntax is invalid, it stops and throws a `SyntaxError`.

### 5. Line-by-line annotated code
```python
print("hello", "world")
```

- `print` — The name of the built-in function we call to display text.
- `(` — Opening parenthesis.
- `"hello"` — A string literal (text data).
- `,` — A comma separating the arguments.
- `"world"` — Another string literal.
- `)` — Closing parenthesis.

What actually happens:
1. Python sees the `print` function.
2. It sees the argument `"hello"`.
3. It sees another argument `"world"`.
4. It prints `hello world` to the screen.

*Tip*: You can have an expression statement that doesn't print anything to the screen. For example, `1 + 2` is an expression that evaluates to `3`. But if you don't use `print()`, the value `3` is lost.

### 6. When to use / when NOT to use
- **When to use**: Everywhere. Every program is made of statements and expressions.
- **When NOT to use**: Never. This is fundamental.

### 7. Sibling comparison (the four pairings beginners confuse)
- **Statement vs. expression**: A statement is an instruction that does something (print, assign, if). An expression is something that produces a value (2 + 2, len("abc")).
- **Syntax vs. semantics**: Syntax is the grammar (does the code parse?). Semantics is the meaning (does the code do what you intended?).
- **SyntaxError vs. NameError**: A `SyntaxError` means the file failed a grammar check before running. A `NameError` means the grammar was fine, but the name you used doesn't exist.

### 8. Under the hood
If you type an expression directly into the REPL (like `2 + 2`), Python will automatically print the result. But if you put `2 + 2` in a `.py` file, it will not print anything. You must use `print()` to see the result.

## §2 — Indentation

### 1. The problem this solves
In other languages (like C or Java), you use curly braces `{ }` to group code. Python uses indentation (spaces at the start of a line) to group code. This makes Python code look cleaner, but it means that if you mess up the spaces, your program breaks.

### 2. Mental model
Indentation is like the margin of a page. Lines that are aligned at the same margin belong to the same block of text.

### 3. Full syntax
```python
if True:
    print("This is inside the if block")
print("This is outside the if block")
```
The `if` statement requires a colon `:` and then a block of indented code.

### 4. Behavior step-by-step
1. Python sees an `if` statement and expects a block of code.
2. The block must be indented (usually 4 spaces).
3. The block ends when the indentation returns to the previous level.

### 5. Line-by-line annotated code

**Valid:**
```python
if 3 > 2:
    print("Yes")
```
- `if 3 > 2:` — The condition. If true, execute the block.
- `    print("Yes")` — The indented block. This runs if the condition is true.

**Invalid:**
```python
if 3 > 2:
print("Yes")  # IndentationError
```
- The `print` statement must be indented. Python will throw an `IndentationError`.

### 6. When to use / when NOT to use
- **When to use**: Every time you write a block of code (if, for, while, function definition).
- **When NOT to use**: When you are just writing a single line of code, no indentation is needed.

### 7. Sibling comparison
- **Indentation vs. braces**: Braces `{ }` are for compilers. Indentation is for humans and Python interpreters.
- **Tabs vs. Spaces**: Never mix tabs and spaces. Use 4 spaces for indentation.

### 8. Under the hood
Python uses indentation to create "blocks". The number of spaces is flexible (you can use 2, 4, or 8), but you must be consistent within the same block. Most Python developers use 4 spaces.

## §3 — Comments

### 1. The problem this solves
Code tells the computer what to do, but it doesn't always tell the *human* what the code means. Comments are notes in the code that the Python interpreter ignores.

### 2. Mental model
A comment is like a note in the margin of a book. The reader (Python) ignores it, but it helps the human reader understand the context.

### 3. Full syntax
```python
# This is a comment
```
Anything after the `#` on a line is ignored by Python.

### 4. Behavior step-by-step
1. Python reads the file.
2. When it hits a `#`, it ignores the rest of the line.

### 5. Line-by-line annotated code
```python
# Calculate the total
total = 1 + 2
```
- `# Calculate the total` — A comment. Python ignores it.
- `total = 1 + 2` — Actual code that executes.

### 6. When to use / when NOT to use
- **When to use**: To explain *why* the code does something. To leave TODOs. To temporarily disable code.
- **When NOT to use**: Don't use it to explain *what* the code does (the code should be readable enough to explain itself).

### 7. Sibling comparison
- **Comment vs. String**: `"# This is a string, not a comment"` is not a comment. It's a string that contains the `#` character.
- **Comment vs. Docstring**: Comments start with `#`. Docstrings are triple-quoted strings used to document functions and classes.

### 8. Under the hood
In Python, `#` comments are completely stripped out during the tokenization process. They don't affect the performance of the code at all.
